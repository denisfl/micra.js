Recipe: a resource() helper

Every data page repeats the same loading / error / data dance around this.fetch(). This ~15-line helper collapses it into one reactive object — { data, loading, error, refetch } — that you drive straight from the template. It lives in your project, not the core bundle: the engine stays under 7 KB and you own the code (same model as the component catalog).

The helper

Drop this into your project (e.g. resource.js). It touches no Micra internals — it only calls the built-in instance.fetch() and writes a top-level state key, so every transition fires a render through the normal shallow proxy. 

// resource.js
export function resource(instance, key, url, options = {}) {
  let ctrl
  const set = (s) => { instance.state[key] = { ...s, refetch } }
  function refetch(overrides = {}) {
    ctrl?.abort()                                  // cancel any in-flight request
    ctrl = new AbortController()
    set({ data: null, loading: true, error: null })
    instance.fetch(url, { ...options, ...overrides, signal: ctrl.signal })
      .then((data)  => set({ data, loading: false, error: null }))
      .catch((error) => {
        if (error.name !== 'AbortError') set({ data: null, loading: false, error })
      })
    return refetch
  }
  return refetch()
}

Using it

import { resource } from './resource.js'

Micra.define('users-table', {
  state: { users: { loading: true, data: null, error: null } },
  onCreate() {
    resource(this, 'users', '/api/users')   // sets state.users through its lifecycle
  },
  fail() {
    // overrides merge into the fetch options (here: a ?fail=1 query param)
    this.state.users.refetch({ fail: 1 })
  },
})
<p data-if="users.loading">Loading…</p>
<p data-if="users.error">Couldn't load.</p>

<table data-show="users.data">
  <template data-each="users.data" data-key="id">  <!-- null while loading → no rows -->
    <tr><td data-text="item.name"></td></tr>
  </template>
</table>

<button @click="users.refetch()">Reload</button>
<!-- refetch with args, e.g. { page: 2 }, goes through a method (see fail() above) -->

Why this fits the shallow proxy

  • Each transition replaces the top-level key. instance.state[key] = {…} is a top-level write, so the proxy schedules a render. No deep reactivity needed — the resource object is swapped wholesale on every state change (loading → data / error).
  • refetch rides on the object. It's a property of the resource, so the template can call users.refetch() directly (member calls are supported in directive expressions). For argument objects like { page: 2 }, call it from a method — directive expressions don't parse object literals.
  • Stale responses can't win. Each refetch aborts the previous request, so a slow first response can't overwrite a fresher one.

Pitfalls

  • Pass { page: 2 } from a method, not inline. Micra's CSP-safe expression evaluator deliberately doesn't parse object literals — keep that logic in a method (@click="loadPage").
  • Don't mutate the resource in place. users.loading = false won't render (shallow proxy). Always go through set() / a fresh object — which the helper does for you.
  • Abort on unmount if a request can outlive the component. The helper aborts on each refetch; if you tear down mid-flight, hold the returned handle and call its controller's abort() in onDestroy.
